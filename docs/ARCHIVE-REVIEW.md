# Archive Review Checklist

An issue is a lead, not a publication. A pull request is ready only after a contributor has completed this checklist.

## Before writing

- Identify the exact event or document and choose one archive category.
- Record the event date separately from the date the entry was added.
- Prefer an official statement, regulator, court record, standard, academic paper, or government document.
- Check whether the proposed record contains personal data, operational details, or information that could put someone at risk.

## During review

- Read each important source, rather than treating a resolving URL as proof.
- Match every strong factual statement to a source.
- Label a statement as `fact`, `source-claim`, `researcher-analysis`, or `editorial`.
- Record affected data only when the source names it.
- Avoid unsupported totals, attribution, motive, and severity claims.
- Mark the entry `unchecked` or `unverified` when the evidence has not been fully reviewed.

## Before merge

- Use a descriptive, stable slug.
- Add related guides or archive entries only when they exist.
- Confirm that the summary is original writing and not a republished article.
- Run the private site validation and build before publication.
- Leave a correction trail in the pull request when an existing entry changes.
